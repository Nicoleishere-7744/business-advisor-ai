# پلتفرم مشاوره کسب‌وکار با هوش مصنوعی

کاربر با شماره موبایل وارد می‌شود (کد یک‌بارمصرف از **آی‌پی‌پنل**)، اطلاعات کسب‌وکارش را در یک فرم
داینامیک وارد می‌کند، هزینه مشاوره را از طریق **درگاه زیبال** می‌پردازد و یک گزارش تحلیلی که با
**OpenRouter** تولید شده تحویل می‌گیرد. پس از گزارش می‌تواند تعداد محدودی سوال پیگیری بپرسد.

- **استک:** Next.js 15 (App Router) · TypeScript · Tailwind CSS v4 · Prisma
- **دیتابیس:** SQLite در توسعه، PostgreSQL در پروداکشن
- **رابط کاربری:** کاملاً فارسی و RTL

---

## راه‌اندازی سریع

```bash
npm install
cp .env.example .env      # مقادیر را پر کن (پایین‌تر توضیح داده شده)
npm run db:sqlite         # provider را روی sqlite می‌گذارد
npx prisma migrate dev
npm run db:seed           # ادمین، فیلدهای فرم، پرامپت و مدل‌های پیش‌فرض
npm run dev
```

سپس به `http://localhost:3000` برو. با شماره‌ای که در `ADMIN_PHONES` گذاشته‌ای وارد شو تا به
`/admin` دسترسی داشته باشی.

### تولید کلیدهای امنیتی

```bash
node -e "console.log('JWT_SECRET='+require('crypto').randomBytes(48).toString('base64url'))"
node -e "console.log('APP_ENCRYPTION_KEY='+require('crypto').randomBytes(32).toString('hex'))"
```

`APP_ENCRYPTION_KEY` باید دقیقاً ۶۴ کاراکتر hex باشد؛ کلیدهای حساس با آن (AES-256-GCM) در
دیتابیس رمزنگاری می‌شوند.

## متغیرهای محیطی

| متغیر | توضیح |
| --- | --- |
| `DATABASE_URL` | `file:./dev.db` برای SQLite یا رشته اتصال PostgreSQL |
| `APP_URL` | آدرس پایه اپ؛ برای ساخت `callbackUrl` درگاه استفاده می‌شود |
| `JWT_SECRET` | کلید امضای نشست (حداقل ۳۲ کاراکتر) |
| `APP_ENCRYPTION_KEY` | کلید رمزنگاری تنظیمات حساس (۶۴ کاراکتر hex) |
| `AI_BASE_URL` | پیش‌فرض `https://openrouter.ai/api/v1`؛ برای رله خارجی همین را عوض کن |
| `OPENROUTER_API_KEY` | کلید OpenRouter |
| `IPPANEL_TOKEN` / `IPPANEL_FROM` / `IPPANEL_OTP_PATTERN` | تنظیمات پیامک |
| `SMS_DEV_MODE` | `true` یعنی کد ورود به‌جای پیامک در کنسول سرور چاپ شود |
| `ZIBAL_MERCHANT` | شناسه پذیرنده؛ مقدار `zibal` حالت سندباکس است |
| `ADMIN_PHONES` | شماره‌هایی که هنگام seed نقش ادمین می‌گیرند (با کاما) |

همه این مقادیر (جز موارد مربوط به دیتابیس و کلیدهای امنیتی) از **پنل مدیریت ← تنظیمات** هم قابل
تغییرند و مقدار ذخیره‌شده در دیتابیس بر متغیر محیطی اولویت دارد.

## نکات مهم پیاده‌سازی

**فرم داینامیک.** فیلدها در جدول `FormField` تعریف می‌شوند و از پنل مدیریت قابل افزودن/ویرایش‌اند.
اسکیمای اعتبارسنجی zod در سرور از روی همان رکوردها ساخته می‌شود، پس اعتبارسنجی کلاینت و سرور
همیشه یکی است. هنگام ثبت مشاوره، اسنپ‌شات فیلدها ذخیره می‌شود تا تغییرات بعدی فرم گزارش‌های
قدیمی را خراب نکند.

**پرامپت.** قالب فعال در `PromptTemplate` نگهداری می‌شود و `{{field_key}}` با پاسخ کاربر جایگزین
می‌شود. هر فیلد فعالی که در قالب استفاده نشده باشد، خودکار در بخش «اطلاعات تکمیلی» به انتهای پیام
اضافه می‌شود؛ بنابراین افزودن فیلد جدید نیازی به ویرایش قالب ندارد.

**تولید گزارش.** پاسخ به‌صورت استریم به کلاینت می‌رود، ولی نوشتن در دیتابیس مستقل از اتصال کلاینت
انجام می‌شود؛ اگر کاربر وسط کار صفحه را ببندد، گزارش کامل ذخیره می‌شود. اگر وضعیت بیش از ۵ دقیقه
روی `generating` بماند، امکان تولید مجدد فعال می‌شود. خطاها وضعیت را `failed` می‌کنند و کاربر
**بدون پرداخت مجدد** می‌تواند دوباره تلاش کند.

**پرداخت.** تأیید تراکنش ایدمپوتنت است: باز کردن دوباره کال‌بک، رکورد تکراری نمی‌سازد و کد تخفیف را
دوباره مصرف نمی‌کند. مبلغ برگشتی از زیبال با مبلغ ذخیره‌شده مقایسه می‌شود و در صورت عدم تطابق
تراکنش رد می‌شود. تخفیف ۱۰۰٪ اصلاً به درگاه نمی‌رود.

**امنیت.** کلیدهای حساس رمزنگاری‌شده ذخیره می‌شوند و هرگز به کلاینت نمی‌روند؛ در پنل فقط وضعیت
«تنظیم‌شده/نشده» نمایش داده می‌شود و خالی گذاشتن فیلد یعنی «تغییرش نده». محدودسازی نرخ روی
درخواست کد ورود، تولید گزارش و چت فعال است. همه مسیرهای تغییردهنده هدر `Origin` را بررسی
می‌کنند و کوکی نشست `httpOnly` + `SameSite=Lax` است.

**سازگاری SQLite و PostgreSQL.** در اسکیما از enum بومی، آرایه و ستون Json استفاده نشده؛ همه‌جا
`String` است و مقادیر مجاز در `src/lib/constants.ts` تعریف شده‌اند. `scripts/set-db-provider.mjs`
فقط خط `provider` را عوض می‌کند.

## تست دستی سرتاسری

۱. **ورود:** با `SMS_DEV_MODE=true` شماره را وارد کن و کد را از کنسول سرور بردار.
۲. **فرم:** از `/admin/form` یک فیلد اضافه یا غیرفعال کن و ببین بلافاصله در `/consultation/new`
   منعکس می‌شود.
۳. **پرداخت سندباکس:** با `ZIBAL_MERCHANT=zibal` یک پرداخت کامل انجام بده. بعد همان آدرس کال‌بک را
   دوباره باز کن؛ نباید چیزی دوباره ثبت شود.
۴. **گزارش:** وسط استریم تب را ببند و صفحه را رفرش کن؛ گزارش باید کامل ذخیره شده باشد و در
   `/admin/usage` یک رکورد هزینه ثبت شده باشد.
۵. **تعویض مدل:** در `/admin/models` مدل پیش‌فرض را عوض کن؛ مشاوره بعدی باید با همان مدل ثبت شود.
۶. **چت:** تا سقف تعیین‌شده سوال بپرس؛ پیام بعدی باید با خطای فارسی رد شود.

## آماده‌سازی برای پروداکشن

```bash
npm run db:pg                      # provider را روی postgresql می‌گذارد
# DATABASE_URL را به رشته اتصال Postgres تغییر بده
npx prisma migrate deploy
npm run build && npm start
```

چک‌لیست:

- [ ] `SMS_DEV_MODE=false` و توکن واقعی آی‌پی‌پنل + کد پترن ثبت شده باشد
- [ ] `ZIBAL_MERCHANT` شناسه پذیرنده واقعی باشد (نه `zibal`)
- [ ] `APP_URL` دامنه واقعی با `https` باشد تا `callbackUrl` درست ساخته شود
- [ ] `JWT_SECRET` و `APP_ENCRYPTION_KEY` مقدار تازه و اختصاصی پروداکشن داشته باشند
- [ ] اگر سرور در ایران است، `AI_BASE_URL` را به رله/پروکسی خارجی سازگار با OpenRouter تغییر بده
- [ ] قیمت مشاوره و سقف چت پیگیری را در `/admin/settings` تنظیم کن
